The Tasks module has no `services/` directory and exposes no public service accessors. Workflow code consumes `workflow-steps/dependency-graph.ts` helpers (called with an explicit `db` handle) plus the `utils/filter-engine.ts` query builder directly.

## DependencyGraphService

Used by the `links` workflow group for cycle detection and graph algorithms.

```ts
wouldCreateCycle(db, sourceId: string, targetId: string): Promise<boolean>
getDependencies(db, taskId: string): Promise<string[]>
getDependents(db, taskId: string): Promise<string[]>
topologicalSort(db, taskIds: string[]): Promise<string[]>
getCriticalPath(db, projectId: string): Promise<CriticalPathResult>
buildDependencyGraph(db, taskIds: string[]): Promise<TaskDependencyNode[]>
```

- `wouldCreateCycle` performs BFS from `targetId` following `blocks` links, returning `true` if `sourceId` is reachable.
- `topologicalSort` uses Kahn's algorithm (in-degree queue). Throws if a cycle is detected.
- `getCriticalPath` computes the longest path by estimated hours using a topological traversal, returning `{ duration, path }`.
- `buildDependencyGraph` returns nodes with their `dependsOn` arrays for client-side rendering.
- Only `blocks`-type links are considered for graph operations.

## FilterEngine

Lives under `utils/filter-engine.ts`. Used by `tasks.list` to build Drizzle WHERE clauses from `TaskFilters`.

```ts
buildTaskWhereClause(filters: TaskFilters | undefined): SQL | undefined
```

- `buildTaskWhereClause` supports: `projectId`, `statusId`, `typeId`, `priority`, `reporterId`, `parentId` (null = top-level), `isArchived`, `label` (array contains), `search` (ilike on title + description), `assigneeId` (correlated `exists` on `task_assignee`).
