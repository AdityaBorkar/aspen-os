The `PubSubUnit` (`$name: "pubsub"`) provides a typed publish/subscribe messaging system backed by [pg-boss](https://github.com/timgit/pg-boss), a Postgres-based job queue. There is always exactly one pg-boss — the single control-plane boss.

## Configuration

```ts title="src/server/pubsub/types.ts"
interface PubSubConfig {
  monitorStateIntervalSeconds?: number; // default: 30
  schema?: string;                      // pg-boss schema (only when SSL)
}
```

<Callout type="info">
  PubSub creates its own pg connection pool (via pg-boss) — it does not reuse `DatabaseUnit`'s pool. Connection details are copied from the DB unit config.
</Callout>

### Example

```ts
const pubsubConfig: PubSubConfig = {
  monitorStateIntervalSeconds: 30,
};
```

## Public API

```ts title="src/server/pubsub/index.ts"
class PubSubUnit {
  readonly $name = "pubsub";

  setAuth(auth: AuthUnit): void;   // wired once during createCore()

  // Publishing
  async publish<T extends object>(
    topic: string,
    data: T,
    options?: PublishOptions,
  ): Promise<string | undefined>;

  async publishBatch<T = unknown>(
    topic: string,
    messages: { data: T; options?: PublishOptions }[],
  ): Promise<string[]>;

  // Subscribing
  async subscribe<T = unknown>(topic: string, handler: MessageHandler<T>): Promise<void>;
  async unsubscribe(topic: string): Promise<void>;

  // Scheduling
  async schedule(topic: string, cron: string, data?: unknown, options?: ScheduleOptions): Promise<void>;
  async unschedule(topic: string): Promise<void>;
  async getSchedules(): Promise<unknown[]>;

  // Queue management
  async getQueueSize(topic: string): Promise<number>;
  async purgeQueue(topic: string): Promise<void>;

  // Diagnostics
  getUnsubscribedProducedTopics(): string[];

  async $prepareInfra(): Promise<void>;  // no-op — boss starts lazily
  async $cleanup(): Promise<void>;
}
```

## Features

### Publish Messages

```ts
// Simple publish
const jobId = await p.pubsub.publish("organization:created", {
  organization: { id: "org-1", name: "Acme Corp" },
});

// Publish with options
await p.pubsub.publish(
  "compliance:document_expiring",
  { documentId: "doc-1", daysUntilExpiry: 7 },
  {
    retryLimit: 3,
    retryDelay: 60,
    retryBackoff: true,
    expireInMinutes: 60,
    priority: 1,
    startAfter: new Date("2024-12-31"),
  },
);
```

<Callout type="warn">
  Publishing to a topic with no registered subscriber (no `subscribe()` call → no pg-boss worker) is **silently dropped** — `send()` returns `null` because the INSERT matches no queue row. `publish()` logs a warning and returns `undefined` in this case. `getUnsubscribedProducedTopics()` and `healthCheck().unsubscribedTopics` surface these for monitoring.
</Callout>

### Batch Publishing

```ts
await p.pubsub.publishBatch("notifications:send", [
  { data: { userId: "1", message: "Hello" } },
  { data: { userId: "2", message: "World" }, options: { priority: 2 } },
]);
```

### Subscribe to Topics

```ts
await p.pubsub.subscribe(
  "organization:created",
  async (message) => {
    console.log("Received:", message.data);
    console.log("Job ID:", message.id);
    console.log("Created:", message.createdOn);
  },
);
```

The handler's `ctx.db` (via `getContext()`) is the tenant DB when running in isolated mode with a per-tenant subscription; otherwise it is the control-plane DB.

### Cron-Based Scheduling

```ts
// Daily at 8am
await p.pubsub.schedule("compliance:daily-expiry-scan", "0 8 * * *");

// Weekly summary every Monday at 9am (IST)
await p.pubsub.schedule("compliance:weekly-summary", "0 9 * * 1", {}, { tz: "Asia/Kolkata" });

// List / cancel
const schedules = await p.pubsub.getSchedules();
await p.pubsub.unschedule("compliance:weekly-summary");
```

### Queue Management

```ts
const size = await p.pubsub.getQueueSize("compliance:document_expiring");
await p.pubsub.purgeQueue("notifications:send");
```

`getQueueSize()` works on unregistered topics and is used by the platform health check as the pubsub connectivity probe.

## Publish Options

```ts title="src/server/pubsub/types.ts"
interface PublishOptions {
  expireInMinutes?: number;   // job expiration
  priority?: number;          // higher = processed first
  retryBackoff?: boolean;     // exponential backoff on retry
  retryDelay?: number;        // seconds between retries
  retryLimit?: number;        // max retry attempts
  startAfter?: Date | string; // delayed execution
}

interface ScheduleOptions extends PublishOptions {
  tz?: string;  // timezone for cron schedule
}
```

## Message Structure

```ts title="src/server/pubsub/types.ts"
interface Message<T = unknown> {
  id: string;
  name: string;         // topic name
  data: T;              // message payload
  createdOn: Date;
  completedOn?: Date;
}

type MessageHandler<T = unknown> = (message: Message<T>) => void | Promise<void>;
```

## Usage in Modules

Domain modules register pubsub handlers and schedules in `$prepareRuntime()` and unregister in `$cleanup()`:

```ts
// In module.$prepareRuntime():
await this.pubsub.subscribe("organization:created", this.handleOrgCreated);
await this.pubsub.schedule("daily:cleanup", "0 2 * * *");

// In module.$cleanup():
await this.pubsub.unsubscribe("organization:created");
await this.pubsub.unschedule("daily:cleanup");
```

## Dependency

Receives `{ db: DatabaseUnit }` via constructor injection, and is wired to `auth` via `setAuth(auth)` during `createCore()`. The single control-plane pg-boss is started lazily on first use.
