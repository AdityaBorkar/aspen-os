Platform is the foundation every module builds on — sign-in, data storage, background jobs, files, and reliable multi-step work.

## Sign-in and permissions

- **User accounts** — Create, view, update, and remove login users.
- **Log in and out** — Start and end sessions, and check whether a login is still valid.
- **Roles** — Give users roles such as admin and browse all available roles.
- **Access rules** — Declare who can do what in each module.

## Data and tenancy

- **Automatic tenant data** — Every request automatically uses the right customer's data.
- **Set up tables** — Prepare database tables from all modules at startup.
- **New customer databases** — Create and pre-fill a database for a new customer.
- **Strict isolation** — Keep each customer's rows separate and private.

## Change history

- **Record every change** — Note who changed what and when.
- **Save change with history together** — Store the update and its history safely in one step.
- **See what changed** — Compare before and after values.
- **Search history** — Look up past changes and rebuild a record's story.

## Background jobs

- **Send background work** — Queue a message to be handled later, one at a time or in bulk.
- **Listen for messages** — Subscribe to a message type, or stop listening.
- **Run on a timetable** — Schedule work such as a daily 8am job, and stop it when done.
- **Watch the queue** — See how many jobs wait and clear them if needed.

## Files and quick values

- **Upload and download** — Store files, fetch them back, and share temporary links.
- **Browse folders** — List files stored under a folder.
- **Quick values** — Save, read, and delete small cached values and counters.

## Logs and APIs

- **Write logs** — Record messages by severity from debug to fatal.
- **Search logs** — Look up past logs and see error counts.
- **Type-safe APIs** — Serve API requests with a built-in health check.
- **Reliable multi-step work** — Define trackable workflows with automatic retry for each step.

## Tenancy modes

- **Single, shared, or isolated** — Run one customer, many customers in one database with row-level isolation, or each customer in its own database.
