The platform has two types of composable building blocks: **Units** and **Modules**. They serve different purposes and follow different conventions.

## At a Glance

|                          | Unit                                   | Module                                      |
| ------------------------ | -------------------------------------- | ------------------------------------------- |
| **Purpose**              | Infrastructure service                 | Domain business logic                       |
| **Created by**           | Platform (via `new` in `createCore()`) | Application (via `Module.create()` factory) |
| **Dependency injection** | Constructor injection                  | `$initialize(units)` method                 |
| **Lifecycle prefix**     | `$` (both server and client)           | `$` (both server and client)                |
| **Count**                | Fixed at 8 (required)                  | Unlimited (optional)                        |
| **Schema**               | Owns core schemas                      | Owns domain schemas                         |
| **Example**              | `DatabaseUnit`, `AuthUnit`             | `Organization`, `Compliance`                |

## Unit Interface

A **Unit** is an infrastructure service. There are exactly 8 on the server, all required, and they are created by the platform itself.

```ts title="src/server/index.ts"
interface Unit {
  readonly $name: string;
  $cleanup(): Promise<void>;
  $prepareInfra?(...args: unknown[]): Promise<void>;
}
```

Server units use the `$` prefix for lifecycle methods (`$name`, `$cleanup`, `$prepareInfra`). This avoids collisions with the unit's own public API (e.g. `DatabaseUnit.db` vs `DatabaseUnit.$cleanup()`).

### Key characteristics

- **Fixed set**: Always 8 units — `db`, `audit`, `auth`, `logs`, `pubsub`, `rpc`, `storage`, `kvStore`. You cannot add or remove units.
- **Platform-managed**: Units are instantiated by `createCore()` using `new`. You provide config, not instances. `audit` takes no config.
- **Dependency-injected**: Units receive dependencies via constructor injection (e.g. `new LogUnit(config, { db })`).
- **Schema ownership**: Each unit that persists owns its database schema (auth tables, log table, storage table, kv-store table, `audit_log`, workflow tables). Pushed during `$prepareInfra()`.
- **Not extensible**: You don't create custom units.

## Module Interface

A **Module** is a package of domain logic. Modules are optional, pluggable, and created by the application.

```ts title="src/server/index.ts"
interface Module<N extends string = string> {
  readonly $name: N;
  readonly $dependencies: readonly string[];
  $initialize(units: Record<string, Unit>): void;
  $prepareInfra(): ModuleInfra;
  $prepareRuntime(): void | Promise<void>;
  $prepareTenant?(tenantId: string): Promise<void>;
  $cleanup(): void | Promise<void>;
}
```

### Key characteristics

- **Pluggable**: You choose which modules to include. Pass them as an **array** to the platform's `create(config, modules)`.
- **Application-managed**: Modules are created by the application via their static `create(config)` factory before being passed to the platform.
- **Unit access**: Modules receive unit dependencies via `$initialize(units)`.
- **Schema/ACL declaration**: `$prepareInfra()` returns `ModuleInfra` (DB schemas + ACL + events), merged and applied by the platform.
- **Extensible**: You can create your own custom modules (see [Creating a Custom Module](/docs/platform/custom-module)).

## Side-by-Side Example

### A Unit (DatabaseUnit)

```ts
// Created by createCore() — you provide config, not an instance
const p = SingleTenantPlatform.create(
  {
    db: { host: "localhost", port: 5432, user: "app", password: "secret", database: "app" },
    // ... other 6 configs + audit (no config)
  },
  [orgModule],
);

// Access via proxy
p.db; // → DatabaseUnit
p.getUnit("db"); // → DatabaseUnit
```

### A Module (Organization)

```ts
// Created by the application via its factory
const organization = Organization.create({ country: "INDIA" });

// Passed to Platform.create()
const p = SingleTenantPlatform.create(config, [organization]);

// Access via proxy
p.organization; // → Organization
p.organization.branches; // → BranchWorkflow
p.getModule("organization"); // → Organization
```

## When to Use Which?

- **You work with units** when configuring infrastructure: database connections, auth providers, storage buckets, log levels.
- **You work with modules** when implementing domain logic: organizations, branches, compliance documents, workflows.

You **never** create custom units. You **do** create custom modules for your domain.
