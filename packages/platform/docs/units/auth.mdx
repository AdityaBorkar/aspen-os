The `AuthUnit` (`$name: "auth"`) wraps [better-auth](https://www.better-auth.com) with plugins for admin, organization, username, phone, email OTP, API keys, two-factor, and passkey.

## Configuration

```ts title="src/server/auth/index.ts"
interface AuthConfig extends BetterAuthOptions {}
```

No custom wrapper fields — module ACL is declared via `defineAcl()` and applied by the platform through `applyModuleAcl()`.

```ts
const authConfig: AuthConfig = {
  baseURL: "http://localhost:3000",
  secret: process.env.AUTH_SECRET!,
  session: { expiresIn: 604800 },
  socialProviders: { google: { clientId: "...", clientSecret: "..." } },
};
```

## Features

### User & Session operations

```ts
await p.auth.rest.user.create({ email, password, name });
await p.auth.rest.user.get({ email }); // or { id }
await p.auth.rest.user.update({ id, data: { name } });
await p.auth.rest.user.remove({ id });

await p.auth.rest.session.create({ email, password });
await p.auth.rest.session.validate({ token });
await p.auth.rest.session.invalidate({ sessionId });

await p.auth.rest.user.role.assign({ userId, roleName: "admin" });
await p.auth.rest.user.role.unassign({ userId, roleName: "admin" });
await p.auth.rest.role.list();
await p.auth.rest.otp.get(tokenRef); // in-process 10-min TTL
```

Structure is `resource.action` via the `rest` getter.

### HTTP handler

```ts
await p.auth.fetchHandler(request);
await p.auth.service.handler(request); // equivalent — raw betterAuth instance
```

### Access control

`applyModuleAcl(acl)` re-creates the service with `admin({ ac: createAccessControl(acl) })`. The platform calls it in `$prepareInfra()` with merged ACL.

```ts
import { defineAcl } from "@aspen-os/platform/server";
const acl = defineAcl({ connection: ["create", "update", "archive", "restore"] });
```

<Callout type="info">
  `defineAcl` declares permissions only; enforcement is application-layer (e.g. RPC middleware).
</Callout>

### Schema & ID convention

| Table          | Description                                             |
| -------------- | ------------------------------------------------------- |
| `user`         | `id, email, name, role, phone, username, banned, image` |
| `session`      | `token, userId, expiresAt, ipAddress, userAgent`        |
| `account`      | `providerId, password, accessToken, refreshToken`       |
| `verification` | `identifier, value, expiresAt`                          |

Auth tables do not follow `uuidv7()` — better-auth manages IDs. `role` is `text("role")` on `user`.

### Plugins & Adapter

Plugins: `admin` (receives `ac`), `username`, `organization`, `phoneNumber`, `emailOTP`, `apiKey`, `twoFactor`, `passkey`. Drizzle adapter: `{ camelCase: false, provider: "pg", usePlural: false, transaction: true }`.
