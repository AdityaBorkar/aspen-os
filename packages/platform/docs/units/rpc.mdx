The `RpcUnit` (`$name: "rpc"`) exposes an oRPC router and HTTP handler.

## Configuration

```ts title="src/server/rpc/types.ts"
interface RpcConfig {
  prefix?: string; // default "/api/rpc"
}
```

```ts
const rpcConfig: RpcConfig = { prefix: "/api/rpc" };
```

## Features

### Handling requests

```ts
const result = await platform.rpc.server.handle(request, {
  db: platform.db.db,
  pubsub: platform.pubsub,
});
if (result.matched) return result.response;
// else fall through
```

`handle()` matches `request.url` against `prefix`; `RpcContext` is provided at request time, not construction.

```ts title="src/server/rpc/types.ts"
interface RpcContext {
  db: PostgresJsDatabase;
  pubsub: PubSubUnit;
  tenantId?: string;
}
```

<Callout type="warn">
  Constructor deps `{ auth, db, logs, pubsub }` are not used at construction — context arrives via `handle()`.
</Callout>

### Defining procedures

Procedures are built on `base = os.$context<RpcContext>()`:

```ts title="src/server/rpc/procedures/echo.ts"
import { base } from "#/server/rpc/base";
export const echo = base.handler(async () => ({ echo: "input.message" }));
```

Input validation uses Standard Schema (Valibot); chain schema before handler per oRPC API.

### Router

```ts title="src/server/rpc/router.ts"
export const router = {
  echo: echoProcedure,
  health: { check: healthCheckProcedure },
};
// platform.rpc.router / platform.rpc.server.router
```

### Base handler

```ts title="src/server/rpc/base.ts"
import { os } from "@orpc/server";
// base = os.$context<RpcContext>()
```

Receives `{ auth, db, logs, pubsub }` via injection though only request-time context is used.
