Workflow group via `p.notes`: `notes`.

Scoped notes use `scopeType` + `scopeId` (`<module>:<entity>` registry value, owning row id); both required together; create takes Valibot `{ input }`, update takes `{ id, input }`, `get`/`delete` take `{ id }`. Every mutation writes an audit entry and publishes a `notes:note_*` event.

## Features

### Notes

Access: `p.notes.notes`

First-class notes: quick-capture (`title` optional) or scoped annotation (`masters:contact`, `tasks:task`, `calendar:event`, …). `access` defaults to `personal`; `ownerId` is derived from `actorId`.

```ts
await p.notes.notes.create({
  input: {
    title: "Call notes",
    body: "Follow up on pricing",
    type: "call",
    access: "personal",
    tags: ["sales"],
    scopeType: "masters:contact",
    scopeId: contactId,
  },
});
await p.notes.notes.get({ id });
await p.notes.notes.update({
  id,
  input: { body: "Updated pricing notes", access: "global", tags: ["sales", "urgent"] },
});
await p.notes.notes.delete({ id });
```

`update` with no fields is rejected; `metadata` is replaced wholesale, not merged.

### Listing

```ts
const notes = await p.notes.notes.list({
  filters: {
    scopeType: "masters:contact",
    scopeId: contactId,
    type: "call",
    tags: ["sales"],
    search: "pricing",
    limit: 50,
    offset: 0,
  },
});
```

Results ordered by `createdAt` descending, `limit` defaults to 50 (max 100). `list` is access-scoped (`global OR ownerId = actorId`; skipped for tenant admins). `search` matches `title`/`body` case-insensitively with `%`, `_`, `\` escaped.
