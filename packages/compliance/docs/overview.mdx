The Compliance module manages compliance documents through their full lifecycle — creation, submission, verification, expiry, renewal, and archival — with obligation templates, automated reminders, and audit trails.

## Module

```ts title="src/index.ts"
export class Compliance implements Module {
  static create(config: ComplianceModuleConfig): Compliance;
  readonly $name = "compliance";
  readonly $dependencies: readonly string[] = [];
}
```

`ComplianceModuleConfig`:

| Option | Type | Default | Description |
|---|---|---|---|
| `country` | `"INDIA"` | — | Country-specific configuration |
| `dashboardCacheTtl` | `number?` | `300` | KV cache TTL for dashboard summary |
| `defaultReminderDays` | `number[]?` | — | Days before expiry/due to send reminders |
| `defaultEscalationDays` | `number[]?` | — | Days after expiry to escalate |

## Initialization

```ts
$initialize(units: { db: DatabaseUnit; kvStore: KvStoreUnit; pubsub: PubSubUnit }): void {
  this.#db = units.db;
  this.#pubsub = units.pubsub;
  this.#kvStore = units.kvStore;
}
```

## Runtime

`$prepareRuntime()` registers the module's schedules and handlers:

1. Reminder schedules via `registerReminderSchedules()`
2. Reminder handlers (`registerReminderHandlers`) — needs `ctx.audit`
3. Obligation generator handler (`registerObligationGenerator`)
4. Event-bridge subscriptions (`registerEventBridgeSubscriptions`) — listens to organization events

`$cleanup()` unregisters all of them. `$prepareInfra()` declares the module's ACL, DB schemas, and events.

```ts
p.compliance.audit          // → AuditWorkflow

```

## Scheduled Jobs

| Job Name | Cron | Description |
|---|---|---|
| `compliance:*` (daily expiry scan, daily escalation, daily status transition, obligation generate, weekly summary) | via `registerReminderSchedules()` | Automated compliance scans and summaries |

The exact job names and crons are defined in `src/constants.ts` and registered in `$prepareRuntime()`.
