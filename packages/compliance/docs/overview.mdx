The Compliance module manages compliance documents through their full lifecycle — creation, submission, verification, expiry, renewal, and archival — with obligation templates, automated reminders, and audit trails.

## Module

```ts title="src/module.ts"
export class Compliance implements Module {
  static create(config: ComplianceModuleConfig): Compliance;
  readonly $name = "compliance";
  readonly $dependencies: readonly string[] = [];
}
```

`ComplianceModuleConfig`:

| Option                  | Type        | Default | Description                              |
| ----------------------- | ----------- | ------- | ---------------------------------------- |
| `country`               | `"INDIA"`   | —       | Country-specific configuration           |
| `dashboardCacheTtl`     | `number?`   | `300`   | KV cache TTL for dashboard summary       |
| `defaultReminderDays`   | `number[]?` | —       | Days before expiry/due to send reminders |
| `defaultEscalationDays` | `number[]?` | —       | Days after expiry to escalate            |

## Initialization

```ts
$initialize(units: { db: DatabaseUnit; kvStore: KvStoreUnit; pubsub: PubSubUnit }): void {
  this.#db = units.db;
  this.#pubsub = units.pubsub;
  this.#kvStore = units.kvStore;
}
```

## Runtime

`$prepareRuntime()` registers the module's schedules and handlers:

1. Reminder schedules via `registerReminderSchedules()`
2. Reminder handlers (`registerReminderHandlers`) — needs `ctx.audit`
3. Obligation generator handler (`registerObligationGenerator`)
4. Event-bridge subscriptions (`registerEventBridgeSubscriptions`) — listens to organization events

`$cleanup()` unregisters all of them. `$prepareInfra()` declares the module's ACL, DB schemas, and events.

## Module Structure

```text
packages/compliance/src/
  module.ts             # Module class (Compliance.create, $prepareInfra/Runtime/Cleanup)
  index.ts              # Re-exports module + types
  auth.ts               # ACL declaration
  db-schemas/           # tables + enums (tenant_schemas; control_plane empty)
  types.ts              # DashboardSummary, TimelineEntry, re-exports
  utils/constants.ts    # Enums, defaults, cron schedules, scheduled job names
  pubsub.ts             # COMPLIANCE_EVENTS + event interfaces + ComplianceEventMap
  schemas/              # Valibot input/filter schemas
  workflow-steps/       # fetch-document/obligation/rule, status-derivation
  workflows/
    document.ts (dir)   # lifecycle + reminder/scan queries
    obligation.ts (dir)
    verification.ts (dir)
    audit.ts (dir)
    dashboard.ts (dir)
  services/
    reminder-engine.ts
    obligation-generator.ts
    event-bridge.ts
```

## Scheduled Jobs

| Job Name                             | Cron        | Registered by                      |
| ------------------------------------ | ----------- | ---------------------------------- |
| `compliance:daily-expiry-scan`       | `0 8 * * *` | `registerReminderSchedules()`      |
| `compliance:daily-status-transition` | `0 0 * * *` | `registerReminderSchedules()`      |
| `compliance:daily-escalation`        | `0 9 * * *` | `registerReminderSchedules()`      |
| `compliance:weekly-summary`          | `0 9 * * 1` | `registerReminderSchedules()`      |
| `compliance:obligation-generate`     | `0 6 * * *` | Subscribed only — no cron fires it |

<Callout type="warn">
  `CRON_SCHEDULES.OBLIGATION_GENERATE` (`0 6 * * *`) is defined but never passed to
  `pubsub.schedule()`. The obligation generator subscribes to the topic; trigger it externally or
  via `generatePendingDocuments()` until a schedule is registered.
</Callout>
