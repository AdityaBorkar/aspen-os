The Organization module exposes one workflow group as a flat `Workflow` object: `branches`. Access via the platform proxy key `p.organization`. The organization profile is managed through Masters settings (`p.masters.settings` with `org.*` keys).

## Configuration

```ts title="src/module.ts"
export interface OrganizationConfig {
  country: "INDIA"; // reserved for future country-specific validation; currently unused
}
```

```ts
import { Organization } from "@aspen-os/organization";

const organization = Organization.create(); // defaults to { country: "INDIA" }
```

## Public API

```ts title="src/module.ts"
readonly branches = {
  create: createBranch, // (input: CreateBranchInput)
  get: getBranch, // (input: { id: string })
  list: listBranches, // (input: { filters?: BranchFilters })
  tree: getBranchTree, // (input: {})
  update: updateBranch, // (input: { id: string; patch: UpdateBranchInput })
};
```

### Branches

Access: `p.organization.branches`

Hierarchical branch CRUD, filtered listing, and tree view.

```ts
await p.organization.branches.create({
  name: "HQ Mumbai",
  code: "HQ-MUM",
  type: "headquarters",
  addressLine1: "1 Linking Road",
  city: "Mumbai",
  country: "IN",
});
await p.organization.branches.update({ id, patch: { name: "HQ Mumbai Central" } });
await p.organization.branches.get({ id });

// Hierarchical view (orphans promoted to roots)
// [{ id, name, children: [...] }]
const tree = await p.organization.branches.tree({});

const offices = await p.organization.branches.list({ filters: { type: "office" } });
const inIndia = await p.organization.branches.list({ filters: { country: "IN" } });
```

### Business Rules

- **Single headquarters** — exactly one `headquarters` branch per organization (`ensureNoHeadquartersExists`)
- **Max 5 levels** — hierarchy depth enforced by a single ancestor walk
- **No circular parents** — detected in the same walk; unknown parents and self-parents rejected
- **Code uniqueness** — branch codes unique case-insensitively, uppercased on write
- **Country codes** — validated against ISO 3166-1 alpha-2 at the schema boundary
