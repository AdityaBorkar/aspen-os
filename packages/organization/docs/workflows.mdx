The Organization module exposes two workflow groups as flat `Workflow` objects: `organizations` and `branches`. Access via the platform proxy key `p.organization`.

## Organizations

Access: `p.organization.organizations`

Manages the organization entity itself — branding, logo, profile.

```ts
await p.organization.organizations.create({ name, slug, ... });
const org = await p.organization.organizations.get({ id });
await p.organization.organizations.update({ id, name });
await p.organization.organizations.updateBranding({ id, accentColor, logo });
await p.organization.organizations.uploadLogo({ id, file });
await p.organization.organizations.deleteLogo({ id });
```

## Branches

Access: `p.organization.branches`

Manages hierarchical branch structures.

```ts
await p.organization.branches.create({ organizationId, name, code, type, parentId });
await p.organization.branches.update({ id, name });
await p.organization.branches.activate({ id });
await p.organization.branches.deactivate({ id });
await p.organization.branches.close({ id });
await p.organization.branches.archive({ id });
await p.organization.branches.restore({ id });
await p.organization.branches.get({ id });

// Hierarchical view
const tree = await p.organization.branches.tree({ organizationId });
// [{ id, name, children: [...] }]

const branches = await p.organization.branches.list({ organizationId });
```

### Business Rules

- **Single headquarters** — exactly one branch of type `headquarters` per organization
- **Max 5 levels** — hierarchy depth enforced in the workflow
- **No circular parents** — detected via recursive traversal
- **Code uniqueness** — branch codes must be unique

## Notes

All workflow methods are `Workflow.name(...)` instances with Valibot input validation and platform workflow persistence. Create-style methods take `{ input: CreateXxxSchema }`; update takes `{ id, patch: UpdateXxxSchema }`.
