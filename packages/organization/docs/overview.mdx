The Organization module owns the tenant's hierarchical branches. The organization profile (id, branding, logo) lives in Masters settings (`org.*` keys via `p.masters.settings`).

## Architecture

```text
TENANT DATABASE (tenant_schemas; control_plane_schemas is empty)
  branch ──self-ref──→ branch (parent_branch, max 5 levels)

MODULE (stateless — $initialize / $prepareRuntime / $cleanup are no-ops)
  Organization.create({ country: "INDIA" })
    $prepareInfra() → { auth.acl, db.{control_plane_schemas, tenant_schemas}, events }
    p.organization.branches → { create, get, list, tree, update }
```

## Hierarchical Branches

Branches form a tree via nullable `parentBranch` (a plain text id — no database FK). The single ancestor walk in `validateParentBranch` verifies the parent exists, rejects circular references, and enforces max 5 levels. Codes are uppercased on write and unique case-insensitively; country codes are validated against ISO 3166-1 alpha-2 at the schema boundary. `tree` returns all branches and promotes orphans to roots instead of dropping subtrees.

## Stateless Workflows

One file per action under `workflows/<entity>/<verb>.ts`. All inputs are Valibot schemas (`schemas/`); `update` takes `{ id, patch }` where `undefined` means "column untouched".

## Relationships

| Module     | Direction     | Connection                                                                                                   |
| ---------- | ------------- | ------------------------------------------------------------------------------------------------------------ |
| Masters    | Extracted out | Contacts, addresses, bank accounts, connections, notes, and the `org.*` settings live in `@aspen-os/masters` |
| Management | Provisions    | Seeds tenants against the better-auth org ID; the org profile is stored as `org.*` settings in Masters       |
| Compliance | Subscribes    | Consumes branch events (trade license, fire safety, annual obligations)                                      |
| Platform   | Host          | Provides `db`, `pubsub`, `step`; pushes schemas and merges ACL centrally                                     |

<Callout type="info">
  `OrganizationConfig` (`{ country: "INDIA" }`) is reserved for future country-specific
  validation and currently unused — `Organization.create()` works on its own.
</Callout>

## Access Control

```ts title="src/auth.ts"
export const acl = defineAcl({
  branch: ["create", "read", "update"],
});
```

## Module Structure

```text
packages/organization/src/
  index.ts              # Module class re-exports
  module.ts             # Module class (implements Module)
  auth.ts               # defineAcl() ACL declaration
  pubsub.ts             # Events for the branch group
  db-schemas/           # Per-entity tables (branch)
  types.ts              # Type re-exports
  schemas/              # Valibot validation schemas
    branch.ts           # CreateBranchSchema, UpdateBranchSchema, BranchFiltersSchema
    enums.ts            # BranchTypeSchema
    utils.ts            # BranchCode, CountryCode schemas
  workflows/
    branch/             # create, get, list, tree, update
    utils.ts            # Code uniqueness, HQ guard, parent validation, buildTree
  workflow-steps/       # fetch-branch
  utils/                # toDateOnly (Date → YYYY-MM-DD)
```
