The Organization module defines 2 tables and 2 enums using Drizzle ORM. Both tables are tenant schemas (`tenant_schemas`); `control_plane_schemas` is empty. Contacts, addresses, bank accounts, connections, and notes moved to the **Masters** module (`@aspen-os/masters`).

## Enums

| Enum                  | Table Column          | Values                                                                       |
| --------------------- | --------------------- | ---------------------------------------------------------------------------- |
| `organization_status` | `organization.status` | `active`, `suspended`, `archived`                                            |
| `branch_type`         | `branch.type`         | `headquarters`, `office`, `warehouse`, `store`, `factory`, `remote`, `other` |

## Tables

### `organization`

The root aggregate — one row per tenant business profile, with branding and locale.

| Column                | Type                | Description                                 |
| --------------------- | ------------------- | ------------------------------------------- |
| `id`                  | text (PK)           | UUIDv7                                      |
| `name`                | text                | Organization name                           |
| `slug`                | text (unique)       | URL-safe identifier, auto-derived from name |
| `status`              | organization_status | Default `active`                            |
| `email`               | text                | Contact email                               |
| `phone`               | text                | Contact phone                               |
| `website`             | text                | Website URL                                 |
| `address`             | text                | Free-text address                           |
| `industry`            | text                | Industry                                    |
| `registration_number` | text                | Registration number                         |
| `tax_id`              | text                | Tax ID                                      |
| `founded_date`        | date                | Founded date                                |
| `logo`                | text                | Storage key for logo                        |
| `accent_color`        | text                | Hex color (default `#3B82F6`)               |
| `locale`              | text                | Locale (default `en-US`)                    |
| `timezone`            | text                | Timezone (default `UTC`)                    |
| `metadata`            | jsonb               | Flexible metadata                           |
| `created_at`          | timestamptz         | Creation timestamp                          |
| `updated_at`          | timestamptz         | Last update timestamp                       |

### `branch`

Hierarchical branch structure with a self-referential parent id (no database FK — enforced in the workflow).

| Column          | Type          | Description                         |
| --------------- | ------------- | ----------------------------------- |
| `id`            | text (PK)     | UUIDv7                              |
| `name`          | text          | Branch name                         |
| `code`          | text (unique) | Branch code, uppercased on write    |
| `type`          | branch_type   | Branch type                         |
| `is_active`     | boolean       | Active flag (default `true`)        |
| `parent_branch` | text          | Parent branch id (nullable, no FK)  |
| `address_line1` | text          | Address line 1                      |
| `address_line2` | text          | Address line 2                      |
| `city`          | text          | City                                |
| `state`         | text          | State/Province                      |
| `postal_code`   | text          | Postal code                         |
| `country`       | text          | ISO 3166-1 alpha-2 code, uppercased |
| `email`         | text          | Contact email                       |
| `phone`         | text          | Contact phone                       |
| `manager`       | text          | Branch manager                      |
| `timezone`      | text          | Timezone                            |
| `opened_date`   | date          | Opened date                         |
| `closed_date`   | date          | Closed date                         |
| `capacity`      | integer       | Capacity                            |
| `notes`         | text          | Free-text notes                     |
| `metadata`      | jsonb         | Flexible metadata                   |
| `created_at`    | timestamptz   | Creation timestamp                  |
| `updated_at`    | timestamptz   | Last update timestamp               |

## Relationships

```text
organization ──1:N──→ branch (logical; no database FK)
branch.parent_branch ──self-ref──→ branch.id (logical; cycle/depth enforced in workflow)
```

Structured contacts, addresses, and bank accounts for an org/branch are managed via `p.masters.*` with `entityType`/`entityId` scoping.

## Usage

Rows are read and written through workflows, not direct SQL:

```ts
const org = await p.organization.organizations.get({});
const offices = await p.organization.branches.list({ filters: { type: "office" } });
const tree = await p.organization.branches.tree({});
```
