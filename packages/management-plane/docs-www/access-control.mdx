The Management Plane declares its ACL via `defineAcl()`, which the platform merges from the module's `ModuleInfra.auth.acl` and applies to `AuthUnit` during `$prepareInfra()`.

## Resources & Operations

```ts title="src/auth.ts"
import { defineAcl } from "@aspen-os/platform/server";

export const acl = defineAcl({
  platformUser: ["create", "delete", "read", "update"],
  serviceProvider: ["create", "delete", "read", "update"],
  tenant: ["create", "delete", "read", "update"],
});
```

| Resource | Operations |
|---|---|
| `tenant` | `create`, `read`, `update`, `delete` |
| `serviceProvider` | `create`, `read`, `update`, `delete` |
| `platformUser` | `create`, `read`, `update`, `delete` |

<Callout type="info">
  The ACL is the *declaration* of operations. Role definitions and permission enforcement are application-level concerns — the module exposes the workflows that perform these operations; the host app decides who may call them.
</Callout>

## Wiring

The platform merges this ACL with other modules' ACLs and applies it via `auth.applyModuleAcl()`:

```ts
// In module.$prepareInfra()
$prepareInfra(): ModuleInfra {
  return {
    auth: { acl },
    db: { control_plane_schemas, tenant_schemas },
    events,
  };
}
```
