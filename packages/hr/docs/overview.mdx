The HR module is a domain module for human resources management covering access control (HR users, RBAC roles), employees, attendance, leave, lifecycle, overtime, shifts, and HR setup.

## Module Structure

```text
packages/hr/src/
  index.ts              # HrModule class: $initialize, $prepareInfra, $cleanup, workflow getters
  db-schema.ts          # Drizzle table definitions (control-plane + tenant schemas)
  types.ts              # Public input/output types and shared pipes, re-exported from schemas/
  event-map.ts          # Per-workflow event constants (8 groups)
  schemas/              # Valibot validation schemas
    index.ts            # Re-exports all schemas, types, and enums
    enums.ts            # 26 enum schemas
    utils.ts            # Shared pipes (NameSchema, EmployeeIdSchema, etc.)
    access.ts
    employee.ts
    attendance.ts
    leave.ts
    lifecycle.ts
    overtime.ts
    setup.ts
    shift.ts
  workflows/            # 8 workflow classes
    index.ts
    access.ts
    employee.ts
    attendance.ts
    leave.ts
    lifecycle.ts
    overtime.ts
    setup.ts
    shift.ts
```

## Workflows

| Workflow | Access Path | Manages |
|---|---|---|
| `AccessWorkflow` | `p.hr.access` | HR users, RBAC roles, permissions, role-permission and user-role mappings, branch-wise access |
| `EmployeeWorkflow` | `p.hr.employee` | Employee records, groups, health insurance, skill maps |
| `AttendanceWorkflow` | `p.hr.attendance` | Attendance, check-ins, attendance requests |
| `LeaveWorkflow` | `p.hr.leave` | Leave types, periods, policies, allocations, applications, encashment, block lists, adjustments, ledger |
| `LifecycleWorkflow` | `p.hr.lifecycle` | Onboarding, promotions, transfers, separations, exit interviews, full and final statements |
| `OvertimeWorkflow` | `p.hr.overtime` | Overtime types and overtime slips |
| `SetupWorkflow` | `p.hr.setup` | HR/payroll settings, employment types, departments, designations, grades, holiday lists, holidays |
| `ShiftWorkflow` | `p.hr.shift` | Shift types, locations, assignments, requests, schedules, schedule assignments |

## Schemas

Validation schemas live in `src/schemas/` and are re-exported from `src/schemas/index.ts`. Each domain file defines `Create*Schema`, `Update*Schema`, and `*FiltersSchema` objects with corresponding `InferOutput` types. Shared pipes (`NameSchema`, `EmployeeIdSchema`, `EmailSchema`, `PhoneSchema`) are in `utils.ts`.

<Callout type="info">
  The module is implemented: `$initialize()` instantiates the 8 workflows from the DB unit, `$prepareInfra()` returns a full `ModuleInfra` with control-plane and tenant schemas, ACL, and per-workflow event groups, and `$cleanup()` resets the workflow fields. Workflow getters throw until `$initialize()` has run. Two gaps remain: `HrModule` does not declare `implements Module`, and it lacks `$prepareRuntime()`.
</Callout>
