The Management Plane exposes `tenants`, `serviceProviders`, `organizations`, and `users` via `p.management` (`$name = "management"`).

Workflows validate with Valibot; `create` takes a single input object, `update` takes `{ id, patch }` where `undefined` leaves the column untouched. Mutations write an audit entry and publish a domain event.

## Tenants

Lifecycle, SP assignment, reads and profile updates.

```ts
// Provision
await p.management.tenants.onboard({
  tenant: { name: "Acme", slug: "acme", plan: "pro", serviceProviderId: "sp-1" },
  userId: "user-1",
});

// Lifecycle
await p.management.tenants.activate({ id: tenantId });
await p.management.tenants.suspend({ id: tenantId, reason: "unpaid" });
await p.management.tenants.reactivate({ id: tenantId });
await p.management.tenants.churn({ id: tenantId, reason: "competitor" });

// SP assignment
await p.management.tenants.assignServiceProvider({ tenantId, serviceProviderId: "sp-1" });
await p.management.tenants.unassignServiceProvider({ tenantId });

// Reads & updates
const tenant = await p.management.tenants.get({ id: tenantId });
const tenants = await p.management.tenants.list({
  filters: { status: "active", plan, serviceProviderId, search, limit: 50, offset: 0 },
});
await p.management.tenants.update({ id: tenantId, profile: { name, slug }, companion: { plan } });
```

<Callout type="warn">
  Status changes only via lifecycle transitions; `update` cannot change `status`. Tenant transitions
  throw on wrong source status; SP transitions are idempotent.
</Callout>

## Service Providers

Create, read, update, lifecycle, and assigned-entity listings.

```ts
const sp = await p.management.serviceProviders.create({
  name: "Acme Integrators",
  slug: "acme-integrators",
  email: "ops@acme.com",
});
const sps = await p.management.serviceProviders.list({
  filters: { status: "active", search, limit: 50, offset: 0 },
});
const one = await p.management.serviceProviders.get({ id: spId });
await p.management.serviceProviders.update({ id: spId, patch: { phone: "+91-9999999999" } });
await p.management.serviceProviders.deactivate({ id: spId });
await p.management.serviceProviders.activate({ id: spId });
const tenants = await p.management.serviceProviders.listAssignedTenants({
  spId,
  limit: 50,
  offset: 0,
});
const users = await p.management.serviceProviders.listUsers({ spId, limit: 50, offset: 0 });
```

## Organizations

Platform-level organizations (`managed_organization`).

```ts
const org = await p.management.organizations.create({
  name: "Acme Org",
  slug: "acme-org",
  branding: { logo: "logos/acme.png" },
});
const one = await p.management.organizations.get({ id: orgId });
const orgs = await p.management.organizations.list({ filters: { search, limit: 50, offset: 0 } });
await p.management.organizations.update({ id: orgId, patch: { name: "Acme Central" } });
```

## Users

Create, read, update, delete, and role/SP assignment.

```ts
await p.management.users.create({
  email: "admin@aspen-os.com",
  name: "Admin",
  password: "secret",
  role: "platform_admin",
});
await p.management.users.create({
  email: "field@acme.com",
  name: "Field",
  password: "secret",
  role: "sp_user",
  spId: "sp-1",
});
const users = await p.management.users.list({
  filters: { role: "sp_user", spId: "sp-1", search, limit: 50, offset: 0 },
});
const user = await p.management.users.get({ id: userId });
await p.management.users.update({ id: userId, patch: { name, role, spId } });
await p.management.users.delete({ id: userId });
await p.management.users.assignRole({ id: userId, role: "platform_admin" });
await p.management.users.assignToServiceProvider({ id: userId, spId: "sp-2" });
```

<Callout type="warn">
  `spId` required when the resulting role is `sp_user` and must be absent otherwise; both verify the
  SP exists.
</Callout>
