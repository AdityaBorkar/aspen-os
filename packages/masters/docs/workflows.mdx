The Masters module exposes seven workflow groups as flat `Workflow` objects: `contacts`, `addresses`, `bankAccounts`, `connections`, `entities`, `paymentMethods`, and `unitsOfMeasure`. Access via the platform proxy key `p.masters`.

Polymorphic entities (`contacts`, `addresses`, `bankAccounts`, `connections`, `paymentMethods`) require `entityType` and `entityId` (the owning `organization`, `branch`, `connection`, `contact`, or `entity`) on create/list; list queries filter on the `(entityType, entityId)` pair. `entities` and `unitsOfMeasure` are tenant-level — no scope pair.

## Configuration

```ts title="src/module.ts"
export type MastersModuleConfig = undefined;

Masters.create(); // $name = "masters" (proxy key: p.masters), $dependencies = []
```

Create-style methods take Valibot-validated input (`CreateXxxSchema`); update takes `{ id, patch: UpdateXxxSchema }`. Each operation writes audit entries (via `ctx.audit`) and publishes domain events via the platform context.

## Public API

```ts title="src/workflows/index.ts"
readonly addresses = { create, delete, get, list, setPrimary, update };
readonly bankAccounts = {
  activate, create, deactivate, delete, get, list, setPrimary, update,
};
readonly contacts = { create, delete, get, list, setPrimary, update };
readonly entities = { create, delete, get, list, setStatus, update };
readonly paymentMethods = {
  activate, create, deactivate, delete, get, list, setPrimary, update,
};
readonly unitsOfMeasure = {
  activate, create, deactivate, delete, get, list, update,
};
// connections is a getter bound to the kvStore unit (same verbs + credential ops)
get connections() // { activate, create, deactivate, delete, get, list, rotateCredential, test, update }
```

## Features

### Contacts

Access: `p.masters.contacts`

Standalone contact records (business relationships — `vendor`, `client`, `insurer`, …). Primary contact is scoped per `(entityType, entityId)`.

```ts
await p.masters.contacts.create({ entityType: "organization", entityId, name, type: "insurer", email, isPrimary });
await p.masters.contacts.get({ id });
await p.masters.contacts.update({ id, patch });
await p.masters.contacts.delete({ id });
await p.masters.contacts.setPrimary({ id });

const contacts = await p.masters.contacts.list({ entityType: "organization", entityId, filters? });
```

### Addresses

Access: `p.masters.addresses`

Address records with a primary flag, scoped per `(entityType, entityId)`.

```ts
await p.masters.addresses.create({ entityType: "organization", entityId, line1, city, state, postalCode, country, label });
await p.masters.addresses.get({ id });
await p.masters.addresses.update({ id, patch });
await p.masters.addresses.delete({ id });
await p.masters.addresses.setPrimary({ id });

const addresses = await p.masters.addresses.list({ entityType: "organization", entityId, filters? });
```

### Bank Accounts

Access: `p.masters.bankAccounts`

Bank account records with a primary flag and active toggle, scoped per `(entityType, entityId)`.

```ts
await p.masters.bankAccounts.create({ entityType, entityId, accountHolderName, accountNumber, bankName, ... });
await p.masters.bankAccounts.get({ id });
await p.masters.bankAccounts.update({ id, patch });
await p.masters.bankAccounts.delete({ id });
await p.masters.bankAccounts.setPrimary({ id });
await p.masters.bankAccounts.activate({ id });
await p.masters.bankAccounts.deactivate({ id });

const accounts = await p.masters.bankAccounts.list({ entityType, entityId, filters? });
```

### Connections

Access: `p.masters.connections`

Integration connections to external APIs/entities. Credentials are stored in the platform `kvStore` (referenced by `credentialRef`); the module holds no plaintext secret material.

```ts
await p.masters.connections.create({
  entityType, entityId,
  name, type: "api_key", baseUrl: "https://api.example.com",
  credential: { apiKey: "..." },
});
await p.masters.connections.get({ id });
await p.masters.connections.update({ id, patch });
await p.masters.connections.delete({ id });
await p.masters.connections.activate({ id });
await p.masters.connections.deactivate({ id });

// Endpoint validation — issues a GET to baseUrl (10s timeout) and records lastTestedAt
const result = await p.masters.connections.test({ id });
// { ok, status, testedAt, error? }

// Credential rotation — writes a new kvStore secret and bumps credentialRef
await p.masters.connections.rotateCredential({ id, credential: { apiKey: "..." } });

const connections = await p.masters.connections.list({ entityType, entityId, filters? });
```

### Entities

Access: `p.masters.entities`

Tenant-level business parties (company/institution) with rich metadata (`ENTITY_TYPE`, `ENTITY_STATUS`, taxId, registrationNumber, …). Optional `organizationId` links an entity to an `organization` profile. `code` is unique per tenant.

```ts
await p.masters.entities.create({
  name,
  type: "hospital",
  industry: "Healthcare",
  taxId,
  registrationNumber,
  foundedDate,
  timezone: "Asia/Kolkata",
});
await p.masters.entities.get({ id });
await p.masters.entities.update({ id, patch });
await p.masters.entities.delete({ id });
await p.masters.entities.setStatus({ id, status: "inactive" });

const entities = await p.masters.entities.list({
  filters: { type, status, organizationId, search, limit, offset },
});
```

`setStatus` enforces `ENTITY_STATUS` transitions: `active` ↔ `inactive`, and both → `archived` (terminal).

### Payment Methods

Access: `p.masters.paymentMethods`

Modes of payment scoped per `(entityType, entityId)`. Type-specific fields are validated: `card` requires `cardBrand`/`cardLast4`/`cardExpiryMonth`/`cardExpiryYear` (masked only); `upi` requires `upiId`; `bank_account`/`imps`/`cheque` require `bankAccountId`. `setPrimary` enforces one primary per `(entityType, entityId, direction)`.

```ts
await p.masters.paymentMethods.create({
  entityType: "entity",
  entityId,
  name: "Business UPI",
  type: "upi",
  upiId: "business@okhdfcbank",
  direction: "both",
});
await p.masters.paymentMethods.get({ id });
await p.masters.paymentMethods.update({ id, patch });
await p.masters.paymentMethods.delete({ id });
await p.masters.paymentMethods.setPrimary({ id });
await p.masters.paymentMethods.activate({ id });
await p.masters.paymentMethods.deactivate({ id });

const methods = await p.masters.paymentMethods.list({
  entityType,
  entityId,
  filters: { type, direction, status },
});
```

### Units of Measure

Access: `p.masters.unitsOfMeasure`

Tenant-wide reference data. Exactly one base unit per `category`; derived units reference the category's base with a `conversionFactor`. A UOM referenced as another's `baseUnitId` cannot be deleted.

```ts
await p.masters.unitsOfMeasure.create({
  name: "Kilogram",
  code: "kg",
  category: "mass",
  symbol: "kg",
  isBaseUnit: true,
});
await p.masters.unitsOfMeasure.create({
  name: "Gram",
  code: "g",
  category: "mass",
  isBaseUnit: false,
  baseUnitId: kgId,
  conversionFactor: 0.001,
});
await p.masters.unitsOfMeasure.get({ id });
await p.masters.unitsOfMeasure.update({ id, patch });
await p.masters.unitsOfMeasure.delete({ id });
await p.masters.unitsOfMeasure.activate({ id });
await p.masters.unitsOfMeasure.deactivate({ id });

const units = await p.masters.unitsOfMeasure.list({ filters: { category, isActive } });
```

## Events

| Event                                                                                                          | Trigger                                            |
| -------------------------------------------------------------------------------------------------------------- | -------------------------------------------------- |
| `masters:contact_created`, `masters:contact_updated`, `masters:contact_removed`                                | Contact create / update / delete                   |
| `masters:address_created`, `masters:address_updated`, `masters:address_removed`                                | Address create / update / delete                   |
| `masters:bank_account_created`, `masters:bank_account_updated`                                                 | Account create / update                            |
| `masters:bank_account_activated`, `masters:bank_account_deactivated`                                           | Account activate / deactivate                      |
| `masters:connection_created`, `masters:connection_updated`, `masters:connection_removed`                       | Connection create / update / delete                |
| `masters:connection_status_changed`, `masters:connection_credential_rotated`                                   | Status change / credential rotation                |
| `masters:entity_created`, `masters:entity_updated`, `masters:entity_removed`                                   | Entity create / update / delete                    |
| `masters:unit_of_measure_created`, `masters:unit_of_measure_updated`, `masters:unit_of_measure_removed`        | UOM create / update / delete                       |
| `masters:unit_of_measure_activated`, `masters:unit_of_measure_deactivated`                                     | UOM activate / deactivate                          |
| `masters:payment_method_created`, `masters:payment_method_updated`, `masters:payment_method_removed`           | Payment method create / update / delete            |
| `masters:payment_method_activated`, `masters:payment_method_deactivated`, `masters:payment_method_primary_set` | Payment method activate / deactivate / primary set |

Full payloads: [Events](/docs/masters/events).

## Schema

| Table                    | Description                                            |
| ------------------------ | ------------------------------------------------------ |
| `master_contact`         | Contact record scoped per `(entityType, entityId)`     |
| `master_address`         | Address record scoped per `(entityType, entityId)`     |
| `master_bank_account`    | Bank account scoped per `(entityType, entityId)`       |
| `master_connection`      | Integration connection with `credentialRef` to kvStore |
| `master_entity`          | Tenant-level business party, optional `organizationId` |
| `master_payment_method`  | Payment mode scoped per `(entityType, entityId)`       |
| `master_unit_of_measure` | Tenant-wide unit with base-unit / conversion structure |

Full columns: [DB Schemas](/docs/masters/db-schemas).

## Dependencies

No module dependencies (`$dependencies: []`). The `connections` group binds the platform `kvStore` unit at `$initialize()` for credential storage; all other groups are stateless. Enum values come from `@aspen-os/constants`.
