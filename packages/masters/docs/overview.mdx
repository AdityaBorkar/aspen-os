The Masters module owns **polymorphic tenant master data**: `contact`, `address`, `bankAccount`, `connection`, and `paymentMethod` — plus **tenant-level tables**: `entity` and `unitOfMeasure` reference data. Every polymorphic entity except global contacts is scoped to an owner via a `(entityType, entityId)` pair, where the owner type is one of `organization`, `branch`, `connection`, `contact`, or `entity` (`master_entity_type`). Contacts may also be **global** (no owner) — the org-wide address book absorbed from DMS.

It also owns the single cross-domain **filter view** store (`filterViews`): saved `{ domain, conditions, sort, groupBy }` configurations with `personal`/`global` access, consolidated from tasks saved views, DMS file views, and workspace views. Hosts read the stored conditions and query their own tables — the module never executes a view.

It also owns the tenant **settings** KV (`settings`): `org.*` keys (`org.id`, `org.branding`, `org.logo`) are tenant-wide rows holding the organization profile; every other key is scoped to the acting user (consolidated from the workspace `workspace_setting` surface).

<Callout type="info">
  Masters does not own notes. Free-form annotation notes belong to `@aspen-os/notes`; scope them to a master row with `scopeType = masters:<entityType>`.
</Callout>

`connection` is an integration connection to an external API/entity — it stores `type`, `status`, `baseUrl`, and a `credentialRef` pointing at an encrypted secret in the platform `kvStore`. Credential material is never stored in plaintext; workflows support credential rotation and endpoint testing. Business relationships are modeled as `contact` records with a `type` (`vendor`, `client`, `insurer`, …).

`entity` is a richer business party (company/institution) with legal/trade metadata (`ENTITY_TYPE`, `ENTITY_STATUS`, taxId, registrationNumber, timezone, …). `paymentMethod` models modes of payment (`bank_account`/`card`/`upi`/`imps`/`cheque`) with a `direction`, type-specific detail fields, and a primary flag per owner. `unitOfMeasure` is tenant-wide shared reference data — units with categories, base-unit/conversion-factor structure.

## Dependencies

No module dependencies (`$dependencies: []`). The `connections` group binds the platform `kvStore` unit at `$initialize()` for credential storage; all other groups are stateless.

## Architecture

All nine tables are **tenant schemas** (`master_` prefix); there are no control-plane tables:

```text
TENANT DATABASE
  master_contact, master_address, master_bank_account
  master_connection, master_entity
  master_unit_of_measure, master_payment_method
  master_filter_view
  master_setting
```

The polymorphic scope mirrors the DMS `dms_entity_label` pattern: `entityType` is a pgEnum (`organization` | `branch` | `connection` | `contact` | `entity`) and `entityId` is the owning row's UUIDv7 id — both nullable on `master_contact` for global address-book entries. Primary flags (`isPrimary`) are scoped per `(entityType, entityId)` for bank accounts — for payment methods per `(entityType, entityId, direction)`. `unitOfMeasure` is tenant-wide reference data with no `entityType`/`entityId` pair; `master_setting` rows scope by key prefix instead — `org.*` keys are tenant-wide (`user_id` null), all other keys are per-user.

## Lifecycle

```text
connections: create (stores credential in kvStore, keeps credentialRef) ──▶ check ──▶ lastTestedAt
            └──▶ rotateCredential (new kvStore secret, bumped credentialRef)
            update(patch.status) ──▶ status (active | inactive | expired | revoked)

contacts/addresses: no primary flag; contacts support global (owner-less) rows
  plus soft-remove with reason (`remove`) alongside hard `delete`

bankAccounts: setPrimary enforces one primary per (entityType, entityId)

entities: create / update / delete (update validates status: active ↔ inactive, → archived terminal)

unitsOfMeasure: exactly one base unit per category; derived units reference the
  category's base with a conversionFactor; delete is blocked while referenced as baseUnitId

paymentMethods: setPrimary enforces one primary per (entityType, entityId, direction);
  card data is masked-only (brand/last-4/expiry — never a PAN)

filterViews: create / get / list (access-scoped) / update / delete / duplicate /
  setDefault / getDefault; is_default is unique per (owner, domain, project)

settings: get / set (upsert); `org.*` keys are tenant-wide, all other keys per-user;
  set is audit-logged
```

## What It Exposes

| Getter           | Methods                                                                              |
| ---------------- | ------------------------------------------------------------------------------------ |
| `addresses`      | `create`, `get`, `list`, `update`, `delete`                                          |
| `bankAccounts`   | `create`, `get`, `list`, `update`, `delete`, `activate`, `deactivate`, `setPrimary`  |
| `connections`    | `create`, `get`, `list`, `update`, `delete`, `check`, `rotateCredential`             |
| `contacts`       | `create`, `get`, `list`, `update`, `delete`, `remove`                                |
| `entities`       | `create`, `get`, `list`, `update`, `delete`                                          |
| `filterViews`    | `create`, `get`, `list`, `update`, `delete`, `duplicate`, `setDefault`, `getDefault` |
| `paymentMethods` | `create`, `get`, `list`, `update`, `delete`, `activate`, `deactivate`, `setPrimary`  |
| `settings`       | `get`, `set`                                                                         |
| `unitsOfMeasure` | `create`, `get`, `list`, `update`, `delete`                                          |

The `connections` group is a getter bound to the platform `kvStore` unit (credentials are written to the secret store at create/rotate time). All other groups are stateless `readonly` properties.

## Module Structure

```text
packages/masters/src/
  index.ts              # Module class re-exports + dbSchema namespace
  module.ts             # Module class (implements Module)
  auth.ts               # defineAcl() ACL declaration
  pubsub.ts             # Events across 8 event groups
  db-schemas/           # Per-entity tables + enums
  types.ts              # Type re-exports
  schemas/              # Valibot validation schemas
  services/             # Connection credential + endpoint-test helpers
  workflow-steps/       # Reusable WorkflowSteps (fetch-<entity>.ts + business-rule steps)
  workflows/            # One file per action under workflows/<entity>/<verb>.ts
  utils/                # Audit constants + strip-undefined
```
