The Masters module owns **polymorphic tenant master data**: `contact`, `address`, `bankAccount`, `connection`, `note`, `entity`, and `paymentMethod` — plus **tenant-wide reference data**: `unitOfMeasure`. Every polymorphic entity is scoped to an owner via a `(entityType, entityId)` pair, where the owner type is one of `organization`, `branch`, `connection`, `contact`, or `entity` (`master_entity_type`).

`connection` is an integration connection to an external API/entity — it stores `type`, `status`, `baseUrl`, and a `credentialRef` pointing at an encrypted secret in the platform `kvStore`. Credential material is never stored in plaintext; workflows support credential rotation and endpoint testing. Business relationships are modeled as `contact` records with a `type` (`vendor`, `client`, `insurer`, …).

`entity` is a richer business party (company/institution) with legal/trade metadata (`ENTITY_TYPE`, `ENTITY_STATUS`, taxId, registrationNumber, timezone, …). `paymentMethod` models modes of payment (`bank_account`/`card`/`upi`/`imps`/`cheque`) with a `direction`, type-specific detail fields, and a primary flag per owner. `unitOfMeasure` is tenant-wide shared reference data — units with categories, base-unit/conversion-factor structure.

## Module

```ts title="src/module.ts"
export class Masters implements Module {
  static create(config?: MastersModuleConfig): Masters;
  readonly $name = "masters"; // proxy key: p.masters
  readonly $dependencies: readonly string[] = [];
}
```

The module declares no platform-module dependencies.

## Architecture

All eight tables are **tenant schemas** (`master_` prefix); there are no control-plane tables:

```text
TENANT DATABASE
  master_contact, master_address, master_bank_account
  master_connection, master_note, master_entity
  master_unit_of_measure, master_payment_method
```

The polymorphic scope mirrors the DMS `dms_entity_label` pattern: `entityType` is a pgEnum (`organization` | `branch` | `connection` | `contact` | `entity`) and `entityId` is the owning row's UUIDv7 id. Primary flags (`isPrimary`) are scoped per `(entityType, entityId)` — for payment methods per `(entityType, entityId, direction)`. `unitOfMeasure` is the only non-polymorphic table: it carries no `entityType`/`entityId` pair.

## Lifecycle

```
connections: create (stores credential in kvStore, keeps credentialRef) ──▶ test ──▶ lastTestedAt
            └──▶ rotateCredential (new kvStore secret, bumped credentialRef)
            activate / deactivate ──▶ status (active | inactive | expired | revoked)

contacts/addresses/bankAccounts: setPrimary enforces one primary per (entityType, entityId)
notes: add / list / remove (polymorphic, typed)

entities: create / update / delete / setStatus (active ↔ inactive, → archived terminal)

unitsOfMeasure: exactly one base unit per category; derived units reference the
  category's base with a conversionFactor; delete is blocked while referenced as baseUnitId

paymentMethods: setPrimary enforces one primary per (entityType, entityId, direction);
  card data is masked-only (brand/last-4/expiry — never a PAN)
```

## What It Exposes

| Getter           | Methods                                                                                           |
| ---------------- | ------------------------------------------------------------------------------------------------- |
| `addresses`      | `create`, `get`, `list`, `update`, `delete`, `setPrimary`                                         |
| `bankAccounts`   | `create`, `get`, `list`, `update`, `delete`, `activate`, `deactivate`, `setPrimary`               |
| `connections`    | `create`, `get`, `list`, `update`, `delete`, `activate`, `deactivate`, `test`, `rotateCredential` |
| `contacts`       | `create`, `get`, `list`, `update`, `delete`, `setPrimary`                                         |
| `entities`       | `create`, `get`, `list`, `update`, `delete`, `setStatus`                                          |
| `notes`          | `add`, `list`, `remove`                                                                           |
| `paymentMethods` | `create`, `get`, `list`, `update`, `delete`, `activate`, `deactivate`, `setPrimary`               |
| `unitsOfMeasure` | `create`, `get`, `list`, `update`, `delete`, `activate`, `deactivate`                             |

The `connections` group is a getter bound to the platform `kvStore` unit (credentials are written to the secret store at create/rotate time). All other groups are stateless `readonly` properties.

## Module Structure

```text
packages/masters/src/
  index.ts              # Module class re-exports + dbSchema namespace
  module.ts             # Module class (implements Module)
  auth.ts               # defineAcl() ACL declaration
  pubsub.ts             # Events across 8 event groups
  db-schemas/           # Per-entity tables + enums
  types.ts              # Type re-exports
  schemas/              # Valibot validation schemas
  workflow-steps/       # Reusable WorkflowSteps (fetch-<entity>.ts + business-rule steps)
  workflows/            # One file per action under workflows/<entity>/<verb>.ts
  utils/                # Audit constants + strip-undefined
```
