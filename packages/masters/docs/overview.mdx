The Masters module owns **polymorphic tenant master data**: `contact`, `address`, `bankAccount`, `connection`, and `note`. Every entity is scoped to an owner via a `(entityType, entityId)` pair, where the owner type is one of `organization`, `branch`, `connection`, or `contact` (`master_entity_type`). This replaces the business-relationship model that previously lived in the organization module.

`connection` is **redesigned** as an integration connection to an external API/entity — it stores `type`, `status`, `baseUrl`, and a `credentialRef` pointing at an encrypted secret in the platform `kvStore`. Credential material is never stored in plaintext; workflows support credential rotation and endpoint testing. Business relationships are modeled as `contact` records with a `type` (`vendor`, `client`, `insurer`, …).

## Module

```ts title="src/module.ts"
export class Masters implements Module {
  static create(config?: MastersModuleConfig): Masters;
  readonly $name = "masters"; // proxy key: p.masters
  readonly $dependencies: readonly string[] = [];
}
```

The module declares no platform-module dependencies.

## Architecture

All five tables are **tenant schemas** (`master_` prefix); there are no control-plane tables:

```text
TENANT DATABASE
  master_contact, master_address, master_bank_account
  master_connection, master_note
```

The polymorphic scope mirrors the DMS `dms_entity_label` pattern: `entityType` is a pgEnum (`organization` | `branch` | `connection` | `contact`) and `entityId` is the owning row's UUIDv7 id. Primary flags (`isPrimary`) are scoped per `(entityType, entityId)`.

## Lifecycle

```
connections: create (stores credential in kvStore, keeps credentialRef) ──▶ test ──▶ lastTestedAt
            └──▶ rotateCredential (new kvStore secret, bumped credentialRef)
            activate / deactivate ──▶ status (active | inactive | expired | revoked)

contacts/addresses/bankAccounts: setPrimary enforces one primary per (entityType, entityId)
notes: add / list / remove (polymorphic, typed)
```

## What It Exposes

| Getter         | Methods                                                                                           |
| -------------- | ------------------------------------------------------------------------------------------------- |
| `addresses`    | `create`, `get`, `list`, `update`, `delete`, `setPrimary`                                         |
| `bankAccounts` | `create`, `get`, `list`, `update`, `delete`, `activate`, `deactivate`, `setPrimary`               |
| `connections`  | `create`, `get`, `list`, `update`, `delete`, `activate`, `deactivate`, `test`, `rotateCredential` |
| `contacts`     | `create`, `get`, `list`, `update`, `delete`, `setPrimary`                                         |
| `notes`        | `add`, `list`, `remove`                                                                           |

The `connections` group is a getter bound to the platform `kvStore` unit (credentials are written to the secret store at create/rotate time).

## Module Structure

```text
packages/masters/src/
  index.ts              # Module class re-exports + dbSchema namespace
  module.ts             # Module class (implements Module)
  auth.ts               # defineAcl() ACL declaration
  pubsub.ts             # Events across 5 event groups
  db-schemas/           # Per-entity tables (contact, address, bank-account, connection, note) + enums
  types.ts              # Type re-exports
  schemas/              # Valibot validation schemas
  workflow-steps/       # Reusable WorkflowSteps (fetch-<entity>.ts)
  workflows/            # One file per action under workflows/<entity>/<verb>.ts
  utils/                # Audit constants + strip-undefined
```
