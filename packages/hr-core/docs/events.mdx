---
title: Events
description: Domain event map for the hr-core module.
icon: IconBell
---

The hr-core module defines domain events by group. Events are type-level contracts published as plain string topics via `PubSubUnit`.

## Employee

| Event                     | Payload                                                 | Trigger                |
| ------------------------- | ------------------------------------------------------- | ---------------------- |
| `employee.created`        | `{ employee: { id, employeeId, firstName, lastName } }` | `employee.create`      |
| `employee.updated`        | `{ employee: { id, name }, changes }`                   | `employee.update`      |
| `employee.status_changed` | `{ employeeId, fromStatus, toStatus }`                  | status mutation        |
| `employee.group_created`  | `{ group: { id, name } }`                               | `employee.createGroup` |

## Lifecycle

| Event                                | Payload                                                                 | Trigger                                           |
| ------------------------------------ | ----------------------------------------------------------------------- | ------------------------------------------------- |
| `lifecycle.onboarding_started`       | `{ onboarding: { id, employeeId, startDate } }`                         | `lifecycle.createOnboarding`                      |
| `lifecycle.onboarding_completed`     | `{ employeeId, onboardingId }`                                          | onboarding completion                             |
| `lifecycle.promotion_requested`      | `{ promotion: { id, employeeId, currentDesignation, newDesignation } }` | `lifecycle.createPromotion`                       |
| `lifecycle.promotion_approved`       | `{ promotionId, employeeId, approvedBy }`                               | `lifecycle.approvePromotion`                      |
| `lifecycle.transfer_requested`       | `{ transfer: { id, employeeId, fromDepartment, toDepartment } }`        | `lifecycle.createTransfer`                        |
| `lifecycle.transfer_approved`        | `{ transferId, employeeId, approvedBy }`                                | `lifecycle.approveTransfer`                       |
| `lifecycle.separation_initiated`     | `{ separation: { id, employeeId, exitDate } }`                          | `lifecycle.createSeparation`                      |
| `lifecycle.separation_completed`     | `{ separationId, employeeId }`                                          | `lifecycle.updateSeparation` status → `completed` |
| `lifecycle.exit_interview_scheduled` | `{ exitInterviewId, employeeId, scheduledDate }`                        | `lifecycle.createExitInterview`                   |

## Position

| Event                  | Payload                                                | Trigger                                                                    |
| ---------------------- | ------------------------------------------------------ | -------------------------------------------------------------------------- |
| `position.created`     | `{ position: { id, name, department } }`               | `position.create`                                                          |
| `position.updated`     | `{ position: { id }, changes }`                        | `position.update`                                                          |
| `position.deactivated` | `{ positionId }`                                       | `position.deactivate`                                                      |
| `position.activated`   | `{ positionId }`                                       | `position.activate`                                                        |
| `position.assigned`    | `{ assignment: { positionId, employeeId, fromDate } }` | `position.assignEmployee`                                                  |
| `position.unassigned`  | `{ positionId, employeeId, toDate }`                   | `position.unassignEmployee`, `position.transferAssignment`, reconciliation |
| `position.reassigned`  | `{ employeeId, fromPositionId, toPositionId }`         | `position.transferAssignment`                                              |

## Setup

| Event                           | Payload                                      | Trigger                      |
| ------------------------------- | -------------------------------------------- | ---------------------------- |
| `setup.department_created`      | `{ department: { id, code, name } }`         | `config.departments.create`  |
| `setup.department_moved`        | `{ departmentId, fromParentId, toParentId }` | `config.departments.move`    |
| `setup.department_head_changed` | `{ departmentId, headEmployeeId }`           | `config.departments.setHead` |
| `setup.designation_created`     | `{ designation: { id, name } }`              | `config.designations.create` |
| `setup.holiday_list_created`    | `{ holidayList: { id, name, year } }`        | `config.holidayLists.create` |
| `setup.settings_updated`        | `{ changes }`                                | `config.hr.update`           |

## Access

| Event                          | Payload                                           | Trigger                     |
| ------------------------------ | ------------------------------------------------- | --------------------------- |
| `access.user_created`          | `{ user: { id, employeeId, userId } }`            | `access.createUser`         |
| `access.user_activated`        | `{ hrUserId }`                                    | user activation             |
| `access.user_deactivated`      | `{ hrUserId }`                                    | user deactivation           |
| `access.role_created`          | `{ role: { id, name, isSystem } }`                | `access.createRole`         |
| `access.role_assigned`         | `{ assignment: { hrUserId, roleId, branchId } }`  | `access.assignRoleToUser`   |
| `access.role_revoked`          | `{ hrUserId, roleId, branchId }`                  | `access.removeRoleFromUser` |
| `access.branch_access_granted` | `{ access: { hrUserId, branchId, accessLevel } }` | `access.grantBranchAccess`  |
| `access.branch_access_revoked` | `{ hrUserId, branchId }`                          | `access.revokeBranchAccess` |

<Callout type="info">
  `lifecycle.separation_completed` and `lifecycle.transfer_approved` are consumed internally for
  position reconciliation. Announcements live in `@aspen-os/hr-announcement` (`announcement.*`
  events).
</Callout>
