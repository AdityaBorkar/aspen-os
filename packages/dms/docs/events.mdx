The DMS module defines domain events across 7 event groups. Events are type-level contracts published as plain string topics via PubSub, for cross-module consumers — the per-file activity feed reads the platform `AuditUnit`, not these topics.

## Event Map

### File Events

| Event                                             | Payload                                            | Trigger                       |
| ------------------------------------------------- | -------------------------------------------------- | ----------------------------- |
| `dms:file_uploaded`                               | `{ fileId, batchId?, version, size, contentType }` | Upload / bulk upload          |
| `dms:file_version_added`                          | `{ fileId, version }`                              | New version                   |
| `dms:file_version_reverted`                       | `{ fileId, version }`                              | Version revert                |
| `dms:file_classified`                             | `{ fileId, classId, docNumber }`                   | Triage classify               |
| `dms:file_updated`                                | `{ fileId, changes }`                              | Update / metadata mutations   |
| `dms:file_moved`                                  | `{ file: { id, name, path }, oldPath, newPath }`   | File moved or renamed         |
| `dms:file_downloaded`                             | `{ file: { id, name, ownerId }, userId }`          | File downloaded               |
| `dms:file_expired`                                | `{ fileId, expiryDate }`                           | Expiry scanner                |
| `dms:file_trashed`                                | `{ fileId, deletedBy }`                            | Soft delete                   |
| `dms:file_restored`                               | `{ fileId }`                                       | Trash restore                 |
| `dms:file_purged`                                 | `{ fileId, storageKey }`                           | Permanent delete / auto-purge |
| `dms:file_hold_placed` / `dms:file_hold_released` | `{ fileId, reason }`                               | Legal hold mutations          |

### Folder / Class / Contact Events

| Event                                                                 | Payload                                             | Trigger                        |
| --------------------------------------------------------------------- | --------------------------------------------------- | ------------------------------ |
| `dms:folder_created`                                                  | `{ folder: { id, name, ownerId, parentId, path } }` | Folder created                 |
| `dms:folder_renamed`                                                  | `{ folder: { id, name, path }, oldName }`           | Folder renamed                 |
| `dms:folder_moved`                                                    | `{ folder: { id, name, path }, oldPath, newPath }`  | Folder moved                   |
| `dms:folder_trashed` / `dms:folder_restored` / `dms:folder_purged`    | `{ folderId }`                                      | Folder trash / restore / purge |
| `dms:class_created` / `dms:class_updated` / `dms:class_archived`      | `{ classId }`                                       | Class mutations                |
| `dms:contact_created` / `dms:contact_updated` / `dms:contact_removed` | `{ contactId, reason? }`                            | Contact mutations              |

### Share / Public Link / File View Events

| Event                                                                       | Payload                                                     | Trigger                                               |
| --------------------------------------------------------------------------- | ----------------------------------------------------------- | ----------------------------------------------------- |
| `dms:share_created` / `dms:share_revoked`                                   | `{ shareId, entityId, entityType, granteeType, granteeId }` | Share create / revoke (any grantee type, incl. group) |
| `dms:public_link_created`                                                   | `{ id, entityId, entityType, permission, token }`           | Public link created                                   |
| `dms:public_link_accessed`                                                  | `{ id, entityId, entityType, token, ip, userAgent }`        | Public link resolved                                  |
| `dms:public_link_revoked`                                                   | `{ publicLinkId, entityId, entityType }`                    | Public link revoked                                   |
| `dms:file_view_created` / `dms:file_view_updated` / `dms:file_view_deleted` | `{ fileViewId }`                                            | File view mutations                                   |

## Usage

### Publishing Events

Events are published via `PubSubUnit.publish()`:

```ts
await p.pubsub.publish("dms:file_classified", {
  fileId: "file-1",
  classId: "cls-1",
  docNumber: "DOC-000001",
});
```

### Subscribing to Events

```ts
// e.g. react to newly classified files
await p.pubsub.subscribe("dms:file_classified", async (message) => {
  const { classId, fileId } = message.data;
  // notify downstream systems
});
```

## Event Map Type

```ts title="src/pubsub.ts"
export type DmsEventMap = FileEventMap &
  FolderEventMap &
  ClassEventMap &
  ContactEventMap &
  ShareEventMap &
  PublicLinkEventMap &
  FileViewEventMap;
```

<Callout type="info">
  The event map is a type-level contract — it is not enforced at runtime. Workflows publish events
  as plain string topics.
</Callout>

## Activity Feed vs Events

DMS writes every action to the platform `AuditUnit` (`entityType` `dms:file`, `dms:folder`, `dms:contact`, `dms:class`, `dms:share`, `dms:file_view`) inline in each workflow. The per-file / per-class activity feed (`p.dms.activity.*`) is a projection over those entries, ordered by `seq`. PubSub events are published separately for cross-module integration and are not the source of the activity feed.
