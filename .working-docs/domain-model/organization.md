# Organization Domain Model

> Package: `@aspen-os/organization`. Branches — the tenant's locations. The organization table is removed; the organization profile (id, branding, logo, and other tenant settings) lives in `@aspen-os/masters` settings (`org.*` keys via `p.masters.settings`). Contacts, addresses, bank accounts, connections, and notes moved to `@aspen-os/masters`.

## Aggregates

### Branch (Aggregate Root)

**Identity**: `id` (text, UUID, generated by the `uuidv7` column type)

**Invariants**:

- Code must be unique
- Exactly one headquarters branch per organization (enforced in workflow)
- Hierarchical nesting max 5 levels deep
- No circular parent references

**Lifecycle commands**: `create(input)`, `update(id, input)`, `get(id)`, `list(filters?)`, `tree()`.

**Relationships**: self-referential `parentBranch` FK for hierarchy.

## Invariants & Business Rules

1. **Branch code uniqueness** — enforced by DB unique constraint on `branch.code`.
2. **Single headquarters** — exactly one branch of type `headquarters` per organization (enforced in workflow).
3. **Branch hierarchy depth** — max 5 levels deep (enforced in workflow).
4. **No circular branch parents** — detected via recursive traversal in workflow.
