# Announcement Domain Model

> Package: `@aspen-os/announcement`. Company broadcasts — authoring, audience targeting, scheduling, publishing, delivery snapshots. Depends on `@aspen-os/hr-core` for audience resolution.

## Aggregates

### Announcement (Aggregate Root)

**Identity**: `id` (text, UUID, generated by `uuidv7` column type)

**Invariants**: Status `draft → scheduled → published → archived`. Only `draft`/`scheduled` records are editable or deletable; `published` is immutable except pin/archive; scheduling requires future `scheduledFor`. Publish is idempotent (re-publishing `published` record returns it, no duplicate event or recipients). Audiences (`all` | `hr_users` | `employees` | `branches` | `departments` | `designations` | `groups` | `roles` | `individuals`) resolve at publish time and snapshot to `announcement_recipient`; snapshot carries `user_id` only for recipients with linked HR user. `departments` targeting includes department subtree.

**Lifecycle commands** (via `p.announcement.announcement`): create/update/delete, publish/archive/restore, schedule/cancel-schedule, pin/unpin, get-by-id, list with filters/search, listRecipients (delivery snapshot), getStats (delivery totals from snapshot + read/acknowledgement counts from comms notifications).

## Invariants & Business Rules

1. **No cron** — scheduling is workflow-only (`schedule`/`cancelSchedule` set `scheduled_for`/`status`); `$prepareRuntime()` is empty.
2. **Schema placement** — both tables live in tenant schemas; `control_plane_schemas` is empty.
3. **Publish idempotency** — publishing already-`published` record returns it without duplicating `announcement_recipient` rows or re-emitting `announcement.published`.
4. **Audience resolution reads hr-core tables directly** — `employee` + `hr_user` are queried via raw SQL (not imports), so dependency stays one-directional (`$dependencies = ["hrCore"]`).
5. **Delivery surface** — in-app inbox, read receipts, and out-of-band delivery are owned by `@aspen-os/comms`; announcement produces `announcement.published` only and never reads/writes inbox state (read/acknowledgement stats read `comms_notification` rows directly).
